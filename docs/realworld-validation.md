## How each case is validated

- **Token-level risks (RW-01…RW-07)** — a minimal HTTP service is stood up that
  reproduces the vulnerable behaviour (e.g. accepting an `alg=none` token, or
  verifying an `HS256` token with the RSA *public* key). Keyway's probe engine
  fires its synthetic attack token at it; a probe that the service wrongly
  accepts is reported as a finding. If the server returns `200` to the attack,
  Keyway flags it.
- **Rotation risk (RW-08)** — reproduces OpenFGA's configuration (the
  `MicahParks/keyfunc` v1.x default `RefreshUnknownKID=false`) and asks Keyway's
  blast-radius engine what happens on a key rotation. Keyway answers
  **will_break** — *before* the rotation — from library defaults alone, with
  zero probes. That is exactly the outage described in the cited issue.

## Honesty notes

- These are **reproductions** of the cited failure modes, not live scans of the
  named projects. The citation identifies the real-world class of bug; the code
  next to it recreates that class so the detection can be checked deterministically.
- Sources are the authoritative record for each class: NVD for CVEs, the project's
  own issue tracker for the rotation outage, and RFC 8725 (JWT BCP) / CWE for the
  claim-validation classes.
